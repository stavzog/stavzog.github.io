PROJECT OVERVIEW

A four-person team built a browser-based editor for reusable stitch patterns. I led the design and implementation of the Rust/WebAssembly backend that turns user-authored guide points into deterministic geometry for the frontend.

BACKEND DESIGN

User-generated points (UGPs) express geometric intent. Generators run math algorithms to transform them into interpolated points (IPs). A DAG allows for the chaining of multiple generators to produce complex shapes.

All IPs and UGPs are stored into flat buffers. The frontend reads slices of the buffers and interprets them as shapes. The IP buffer is exported as a sequence of stitch commands for the embroidery machine.

The UGP Binder

Maps user-manipulated guide points to a node and port.

The Port-Aware DAG

Nodes are generator functions, ports are arguments, edges define chains of functions.

The CSR Graph

Flattens the graph into a CSR representation for efficient traversal. Helps nodes identify incoming edges so they can pull input data from the cache.

The Shape Packaging & Frontend Contract

At a terminal node, output becomes a Shape record containing the final IPs, the node that created it, and the generator it used. The Shape record is read by the frontend.

EXECUTION TRACE

TRACE A CIRCLE WITH A ZIGZAG STITCH
  1. 1. Create Guide Points. Two guide points define a circle's center and radius; three more define a V-shaped stitch guide.
  2. 2. Define dependencies. The pattern generator receives the V-shaped guide on port 0 and the circle on port 1.
  3. 3. Execute. Kahn's algorithm runs generators when their required inputs are available; downstream nodes pull inputs from the cache
  4. 4. Package. The terminal generator's interpolated points are returned to the frontend as a Shape record.
